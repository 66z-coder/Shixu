# V1 主程序接线与联调

B #11、C #12、D #10、E #13 已合入 develop。主窗口现在直接使用 V1 服务，不再通过旧三心情推荐路径调用新页面。

## 已接入的用户流程

- 智能录入提交成功后刷新库存与首页，清除推荐换批排除记录。
- 首页和推荐页同步五心情；新推荐服务读取真实菜谱和同一库存快照，日期按 Asia/Shanghai 填入。
- 推荐卡片与菜谱目录均可打开详情；详情查询最新库存并显示营养和缺口。
- 点击“我已做完”生成新 UUID 和固定时间，进入预览。缺少或重量未知的食材逐项确认外部备好，重新预览成功后才能提交。
- 依次扣库存、记饮食、发奖励；失败保留最后已保存阶段，关闭窗口不删除待处理事件。
- “待处理做饭记录”入口在重启后仍可使用。已扣库存只能继续结算；只有 B 明确未扣减的 Prepared 事件允许取消。
- 库存变化后必须重新预览并由用户确认，不会后台重新确认后自动扣减。

## 存储与恢复

库存继续使用工作目录的 shixu.db；饮食继续使用同目录 meal_records.txt；奖励保留 RewardSystem 原有 rewards.ini 默认位置。
新增同目录 cooking_events.sqlite，保存版本化、带 SHA-256 完整性校验的二进制快照和每一步结果，浮点数据不通过显示字符串舍入。
快照包含原始菜谱、食材需求、营养、请求、时间和外部准备清单。重试不重新计算菜谱，也不更换事件编号。

协调服务用独立 SQLite 连接存日志，借用 B/C/E 服务。操作按日志路径锁串行执行；B/C/E 各自的持久化幂等处理弥合“业务已提交、日志未更新”的窗口。
日志读取失败、损坏、B 查询失败均明确报告，不当作没有记录。Cancelled 保留为不可重试的记录。

旧库存别名在主窗口初始化时由 A 的 RecognitionService 规范化，B 只负责在原连接内原子更新名称与 revision；不合并批次、不修改已有消费事件。

## 测试

Qt 6.11.2 / MinGW 13.1 下完整构建，包括 Shixu 主程序。根 CTest 接入原测试及 D/E 独立业务测试，共 25 项。
禁用 Qt 的构建保持 7 项测试。测试使用临时数据库、饮食文件与奖励文件，不依赖个人库存。

新增 CookingCompletionTest 使用真实 B/C/D/E 服务，覆盖：

- 五心情真实 B/C 输入、正常完成、实际临期奖励、重复确认与重启重放。
- C 写入失败、E 写入失败及恢复，验证库存版本、饮食记录数、做饭次数不重复增加。
- 多批库存更新中途 SQL 故障，逐批核对数量与重量回滚，版本和事件也回滚。
- 库存变化、冻结请求冲突、扣减前取消、取消后拒绝重试、扣减后拒绝取消。
- 重启后重新预览及明确确认。
- B 已提交、日志保存失败后重启恢复，验证 B 不再次扣减。
- 旧别名迁移与 revision 推进；日志不可写与内容损坏时停止。

新增 MainWindowFlowTest 在 offscreen Qt 中实际点击：首页心情→推荐卡→详情→外部食材确认→完成→重建主窗口，核对实际库存事件和奖励次数。
原 PackagingIntegrationTest 覆盖录入入库；OCR 测试覆盖协议及已有录入流程，本轮未用摄像头或新拍摄小票做人工识别验收。

构建示例（Qt/编译器路径按本机配置）：

```powershell
cmake -S . -B build-integration -G Ninja -DCMAKE_PREFIX_PATH=<Qt安装目录>
cmake --build build-integration
ctest --test-dir build-integration --output-on-failure
cmake -S . -B build-noqt -G Ninja -DCMAKE_DISABLE_FIND_PACKAGE_QT=TRUE
cmake --build build-noqt
ctest --test-dir build-noqt --output-on-failure
```

限制写入的运行环境下，将 TEMP/TMP 指向构建目录内的可写临时目录。真实应用运行时应使用固定工作目录，避免读取到另一份 shixu.db。

## 成长统计与包装图片拖入

成长页按 C 饮食记录、完成日志和 B 库存消耗事件的同一 eventId 核对，只统计 Completed 的做饭。C 已写入但奖励尚未结算的事件暂不计入，恢复完成后计入一次。旧的无 eventId 饮食记录单独显示，不贡献次数或成就。最近记录显示最后 10 条的菜名、日期和估计营养。

临期利用按每次做饭计一次，依据 B 实际扣减批次 consumedGrams > 0 且 wasExpiring；不按临期批次数重复累计。四个成就为首次完成、连续 3 个自然日完成、累计 3 次临期利用、完成 5 个不同 recipeId。自然日统一使用 Asia/Shanghai。新成就不额外增加积分；原成功做饭积分、每日首次自动打卡与七天打卡记录继续由 E 管理。

成就保存在奖励文件旁的 cooking_achievements.json（version=1，unlocked 数组包含 code 和 unlockedAt）。通过文件锁和原子替换保存，已解锁成就永久保留；重启不会重复颁发。历史完整事件会补算成就。来源缺失、损坏或保存失败显示明确错误，不用零值掩盖失败，不覆盖损坏文件。

包装识别卡及其子控件支持拖入一张本地图片，和选图按钮共用导入流程，按图片方向显示。多张、目录、网络链接和无效图片被拒绝并保留表单。OCR 或提交期间不可替换图片；拖入后仍需主动点击识别。

本轮完整 Qt 测试共 28 项。CookingActivityTest 覆盖真实记录关联、跨日与同日重复、四项成就阈值、重启、失败恢复、取消、来源异常及原子保存失败；MainWindowFlowTest 检查完成做饭后统计自动更新和重新打开后的保留；PackagingDropTest 覆盖拖入各子区域、无效文件保留内容及忙碌状态。无 Qt 构建保持 7 项测试。


## 统一界面与个人偏好

五种心情点击后自动生成真实推荐。默认时长为 30/45/30/40/75 分钟；默认优先库存且允许补购。快捷条件集合与旧 refinement 合并去重；多个排序偏好取平均后使用原 .35 加权强度，不改变基础评分。不吃面、个人避开食材、时间上限与严格库存先过滤，未知数量不会作为库存充足。换批排除当前条件下已展示 ID；条件变更或恢复默认清空批次。

个人资料保存在奖励文件旁的 profile.json（version=1），包含昵称、四种内置头像、默认库存策略与规范食材名称列表。QSaveFile 原子保存；损坏文件禁止覆盖并阻止推荐。个人中心不提供账号登录或云同步。保存后刷新推荐，恢复推荐默认保留个人避开食材。

查看做法定位详情步骤，开始烹饪只改变页面状态，完成后才进入现有结算确认。全局待处理横条已移除，菜谱导航显示待处理数量或读取异常标记。应用使用统一中文字体和蓝白控件样式，成长页展示成就卡片。

验证新增个人资料存储测试，并扩展推荐叠加与去重、UI 自动请求、开始烹饪不结算和多页面尺寸截图检查。


## 我的成长与品牌图标

打卡成长与成长统计的内部路由均进入“我的成长”，导航只保留一个入口。页面仅展示今日操作、四项概览、七天日期、四个烹饪成就及三个原打卡徽章、最多十条已完成做饭；营养详情可展开。旧饮食记录入口隐藏，原记录与服务读取能力保留，不参与统计的规则不变。数据和成就文件无需迁移。

图标源文件位于 resources/icons，包含 SVG、512px PNG，以及 Windows 多尺寸 shixu.ico。图形使用冰箱、番茄和绿叶；成就图标对应厨师帽、火苗、循环叶片和餐具指南针。窗口与侧边栏使用 Qt 资源内 PNG，Windows 可执行文件嵌入 ICO。四张成就卡在页面宽度 850px 及以上为四列，否则两列。

验证：30 项 Qt 测试通过，包括旧入口共用页面、旧数据保留、手动与做饭自动打卡去重、原结算失败恢复和滚轮防误触；980×620、1280×800 与 150% 缩放页面检查通过。

## 2026-10-30 最终交付状态

推荐使用“选择需求 → 查看推荐 → 菜谱详情”三级内嵌页面，结果页为首选与两张备选双栏布局，快捷调整固定在下方。三张卡均可展开真实推荐依据，时间、评分、库存缺口和理由有独立层级。心情与时间为主要评分因素，日常调料不作为补购缺口，连续重复菜谱有轻度降权。首页保留冰箱布景。

菜谱页直接展示食材、做法、营养与完成做饭入口。“我的成长”保留最多十条真实完成记录，并显示当日营养汇总；每日目标独立保存在 nutrition-goals.json，仅参与展示，不影响推荐。个人资料支持导入头像；库存数量显示按单位友好换算，编辑和扣减保留实际精度。

统一按钮、输入框、导航图标、卡片和滚动区域样式，支持 980×620、1280×800、1600×900 及高 DPI 缩放。便携分发使用独立 data 目录和可选 OCR 扩展，详见 [Windows 发布说明](windows-release.md)。
