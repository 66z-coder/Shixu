# A 模块调整：包装日期识别与标准化

Shixu.exe 的“智能录入”页已接入包装识别和手动录入，可提交到 B 库存。food_entry_demo.exe 保留为不入库的独立演示。旧小票界面、商品解析及专属测试已删除；共用本地 OCR 仍保留，安装说明见 [本地 OCR](local_ocr.md)。本次只调整代码与功能说明，没有修改团队分工原文。

## 使用流程

1. 填写食材名称、数量与单位。
2. 可直接手动填写，或导入包装照片识别；也可粘贴标签原文解析。
3. 选择已知到期日、生产日期＋保质期，“从今天起保存”＋预计保存天数，或明确选择“到期日期未知（手动录入）”。
4. 若按保质期计算，统一使用生产日期加完整保质期。按月/年采用日历加法，目标月份无同一天时取月末，界面展示计算规则和最终结果供确认。实际包装不符合该规则时，应改用用户确认的明确到期日。
5. 核对当前食材并勾选确认，点击“添加食材到列表”；表单清空后继续录入下一件。
6. 右侧列表支持双击修改、保存修改、删除。全部录好后点击“确认提交全部食材”，一次输出 FoodCandidate 列表。

主窗口接收 foodsConfirmed，调用 B 的 addFoods 批量事务保存，并通过 completeSubmission 返回结果。提交期间禁用录入页以防重复；成功清空列表、显示条数并刷新库存，失败显示原因并保留整批输入。独立演示也回传结果，但明确标记未入库。

## 不推测的边界

- 只将“生产日期/制造日期/生产时间”以及“有效期至/到期日期/到期日/保质期至/失效日期/最佳食用期至”等明确标签与完整日期关联。
- 支持四位年份的 YYYY-MM-DD、YYYY/MM/DD、YYYY.MM.DD、YYYY年MM月DD日、YYYYMMDD，全角数字及标签与日期换行。
- 无标签喷码、两位年份、批号、无效日期不自动解释；用户可核对后填写完整日期。
- 支持明确的整数天/月/年保质期；缺少生产日期或保质期时不能输出计算结果。
- 多个不同日期、多个保质期、开封/冷藏/冷冻/解冻条件或标注之间不一致时，不自动采用候选字段，保留原文并要求人工选择和补充。
- 不依据食品类别估算保质期。不把日期计算等同于食品安全判断。
- 日期早于今天会提示核对；到期日早于已填写的生产日期不能提交。
- 修改原始文字会清除旧日期结果；修改任何录入字段都清除确认状态。

## 实现

复用本地 OCR 进程和已安装模型（类名 ReceiptOcrService 保留以兼容旧代码），由 PackagingDateParser 完成 C++ 日期解析。PackagingEntryWidget 负责补齐字段、计算预览和显式确认。

resources/recognition/normalization.json 维护名称别名和单位映射，作为 Qt 资源编入程序，修改后重新编译。名称仅精确匹配，未知名称保留；不把苹果汁变为苹果。单位映射只统一写法：公斤→kg、毫升→ml，不改变数值，500克仍为500g。新流程拒绝空单位及映射表外单位，要求用户选择或先维护映射表；标准化辅助函数保留空单位默认值兼容。

示例别名包括西红柿→番茄、马铃薯/洋芋→土豆。食品分类不属于本次改动。

## 验证

packaging_date_test 覆盖标签、日期格式、闰年/月末、固定计算规则、缺失/冲突信息、名称单位映射。packaging_entry_test 覆盖人工补齐、确认前阻止输出、字段变更清除确认、正常输出统一候选。另保留名称单位标准化与本地 OCR 进程协议测试。

构建后执行 ctest --test-dir build --output-on-failure。真实包装上反光、弯曲、点阵喷码和低清晰度会影响 OCR，仍需不同包装样本验证。

## 批量录入更新
当前界面已恢复待提交列表：逐项填写或识别包装后添加，支持双击或按钮修改、删除、取消修改，最后一次输出整批 FoodCandidate。当前表单未保存或正在识别时不能整批提交；已保存条目不会因录入下一件而清空。
起算方式选项已移除，生产日期加完整保质期为固定计算方式。月/年仍采用日历运算并显示结果供确认。
手动录入可明确选择到期日期未知，保持无效 QDate；这不是自动估算。包装识别缺失信息仍会要求补齐，除非用户主动选择未知。
